# PixelShrink — Antigravity 프로젝트 지침

## 프로젝트 목표
브라우저 안에서 이미지 파일을 WebP / PNG / JPG로 변환하고, JPG·WebP 품질을 조절해 용량을 줄이는 반응형 웹 유틸리티를 만든다.

## 작업 원칙
1. 기존 파일과 기능을 먼저 읽고 구조를 파악한 뒤 수정한다.
2. 사용자가 요청하지 않은 프레임워크나 빌드 도구를 임의로 추가하지 않는다. 현재 버전은 HTML/CSS/Vanilla JavaScript 기반 정적 사이트다.
3. 이미지 파일을 서버로 전송하지 않는다. 변환은 Canvas API와 `HTMLCanvasElement.toBlob()`으로 브라우저 내에서 처리한다.
4. 파일명, 확장자, MIME 타입을 일관되게 유지한다.
5. 모든 버튼과 입력은 실제 동작해야 하며, 처리 중 상태·오류·완료 메시지를 사용자에게 보여준다.
6. 한국어 UI를 기본으로 하고 데스크톱과 모바일에서 모두 자연스럽게 동작하도록 한다.
7. 보안상 사용자 파일명을 HTML 문자열로 삽입하지 않는다. DOM의 `textContent`를 사용한다.
8. 외부 라이브러리 의존성은 꼭 필요한 경우에만 추가한다.

## 핵심 기능 요구사항
- 파일 선택 및 드래그 앤 드롭 지원
- 여러 이미지 일괄 추가 및 개별 삭제 / 전체 삭제
- 출력 형식 선택: WebP, PNG, JPG
- 품질 슬라이더: 10~100%, JPG/WebP 인코딩에 적용
- Canvas API로 변환 후 파일 다운로드
- JPG 출력 시 투명 영역은 흰색 배경으로 합성
- 파일별 오류 처리 및 변환 진행 상태 안내
- 변환 전후 용량과 절감률 표시 기능을 다음 개선 단계에서 추가
- 접근성: 키보드로 파일 선택, 명확한 label, aria-live 상태 안내

## 기술 및 품질 지침
- 이미지 크기를 임의로 축소하지 않는다. 품질 압축과 리사이즈는 별도 기능으로 구분한다.
- PNG는 브라우저 Canvas 인코더에서 품질 슬라이더를 표준적으로 지원하지 않으므로 UI에 안내한다.
- 브라우저가 WebP 인코딩을 지원하지 않으면 성공한 것처럼 가장하지 말고 오류를 표시한다.
- 대용량 이미지의 메모리 사용을 고려한다. 객체 URL은 사용 후 `URL.revokeObjectURL()`로 해제한다.
- 파일 확장자만 바꾸지 말고 실제 인코딩된 MIME 타입을 확인한다.
- 변환 결과 파일명은 원본의 마지막 확장자를 제거하고 새 확장자를 붙인다.
- 광고 영역은 현재 자리 표시자만 둔다. 실제 광고 코드는 운영 정책 검토 후 별도로 삽입한다.
- 광고가 변환·다운로드 버튼을 가리거나 오작동하게 배치하지 않는다.

## 디자인 방향
- 다크 네이비 배경, 보라색 주요 액션, 민트색 개인정보 보호 강조
- 간결한 SaaS 유틸리티 UI
- 중앙 정렬 히어로, 점선 드롭존, 변환 설정 패널, 파일 목록, 광고 슬롯, 기능 소개
- 반응형 레이아웃 및 충분한 터치 영역

## 완료 전 테스트
- JPG → WebP / PNG / JPG
- PNG 투명도 유지(WebP/PNG) 및 JPG 변환 시 흰색 배경
- 여러 파일 동시 선택 및 드래그 앤 드롭
- 잘못된 파일과 손상된 이미지 오류
- WebP 미지원 환경에서의 오류 처리
- 모바일 화면에서 파일 선택 및 다운로드
- 파일명에 한글·공백·괄호가 있는 경우
- 변환 전후 파일 크기 표시가 정확한지

## Antigravity 작업 순서
1. 현재 구현을 실행해 기본 동작을 확인한다.
2. 위 요구사항과 기존 코드를 대조해 누락·버그를 정리한다.
3. 기능을 작은 단위로 구현하고 각 단계에서 브라우저 테스트를 수행한다.
4. 수정한 파일, 구현한 기능, 테스트 결과, 알려진 제한사항을 마지막에 요약한다.
